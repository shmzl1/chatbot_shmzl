# 总体功能设计

## 1. 项目定位

本项目是本地 Windows 环境运行的虚拟人物陪伴系统。

系统主功能只有三个：

1. 聊天；
2. 日记；
3. 日程。

其中：

* 聊天：虚拟人物陪伴、问答、情绪回应；
* 日记：记录生活、情绪、图片和复盘素材；
* 日程：管理任务、计划、复习和今日安排。

角色设定和关系记忆不是独立主功能，而是嵌入到聊天、日记、日程中的底层能力。

角色设定负责决定虚拟人物“是谁、怎么说话、有哪些边界”。
关系记忆负责保存用户确认后的长期偏好、习惯和关系理解。

## 2. 总体功能结构

```text
虚拟人物陪伴系统
├─ 聊天
│  ├─ 虚拟人物陪伴
│  ├─ 问答
│  ├─ 情绪回应
│  └─ 调用角色设定与关系记忆
│
├─ 日记
│  ├─ 生活记录
│  ├─ 情绪记录
│  ├─ 图片素材
│  ├─ 复盘素材
│  └─ 用户主动选择后，可让角色阅读或复盘
│
└─ 日程
   ├─ 任务管理
   ├─ 计划管理
   ├─ 复习安排
   ├─ 今日任务
   └─ 用户主动选择后，可让角色辅助安排或提醒
```

底层能力：

```text
角色设定
├─ 固定核心人设
└─ 可变补充人设

关系记忆
├─ pinned / always_read 记忆
├─ 普通 active 记忆
├─ 短期记忆
└─ archived / superseded / deleted 记忆
```

## 3. 主功能边界

### 3.1 聊天

聊天是虚拟人物最直接的交互入口。

聊天负责：

* 虚拟人物陪伴；
* 用户问答；
* 情绪回应；
* 基于角色人设生成回复；
* 读取必要的关系记忆；
* 在用户允许时，围绕某篇日记或某个日程进行交流。

聊天不负责：

* 自动读取全部日记；
* 自动读取全部日程；
* 自动把所有聊天内容写入长期记忆；
* 自动修改角色核心人设。

### 3.2 日记

日记是用户原始生活记录。

日记负责：

* 新建日记；
* 编辑日记；
* 删除日记；
* 按日期查看；
* 保存心情、标签和图片；
* 作为后续复盘素材。

日记不负责：

* 自动进入聊天 prompt；
* 自动生成长期记忆；
* 自动修改角色设定。

只有用户主动选择时，角色才能阅读某篇日记或基于某篇日记进行复盘。

### 3.3 日程

日程是用户行动安排。

日程负责：

* 任务管理；
* 计划管理；
* 今日任务；
* 月历视图；
* 复习安排；
* 完成、延期、跳过；
* 复习反馈。

日程不负责：

* 自动进入聊天 prompt；
* 自动生成长期记忆；
* 自动把所有任务转为用户习惯判断。

只有用户主动选择时，角色才能查看今日任务、某个计划或某次复习结果。

## 4. 角色和记忆的定位

角色和记忆不作为主功能入口优先展示。

正确结构：

```text
聊天 / 日记 / 日程
        ↓
角色设定 + 关系记忆
```

错误结构：

```text
聊天 / 日记 / 日程 / 角色 / 记忆
```

角色和记忆可以放在设置、高级设置或管理页面中，但不作为与聊天、日记、日程并列的主功能。

## 5. 主导航设计

第一阶段主导航建议为：

```text
聊天
日记
日程
设置
```

其中：

* 角色管理放入设置或高级设置；
* 记忆管理放入设置或高级设置；
* 用户头像、显示 ID、本地数据目录等也放入设置。

## 6. 本地单用户原则

项目只考虑 Windows 本地运行。

默认只有一个本地用户。

不需要：

* 注册；
* 登录；
* 多用户权限；
* 云端同步；
* 多端同步。

用户可以：

* 修改本地显示 ID；
* 上传头像；
* 使用聊天、日记、日程；
* 管理角色和记忆。

## 7. 数据安全和隐私原则

日记和日程属于用户原始数据。

默认情况下：

* 日记不进入聊天 prompt；
* 日程不进入聊天 prompt；
* 全部聊天记录不进入长期记忆；
* 全部日记不进入长期记忆；
* 全部日程不进入长期记忆。

只有用户主动触发时，才允许角色读取某篇日记、某个日程或生成候选记忆。

候选记忆必须经过用户确认后，才能写入 relationship_memory。

## 8. 开发阶段

### P1：聊天稳定化

目标：

* 本地默认用户；
* 无登录流程；
* 角色聊天稳定；
* 人设编辑稳定；
* 角色核心人设和可变人设分层；
* 可变人设不无限增长。

### P2：日记 MVP

目标：

* 日记 CRUD；
* Markdown 正文；
* 心情；
* 标签；
* 图片上传；
* 图片预览；
* 图片删除；
* 日记不会自动进入聊天 prompt。

### P3：日程 MVP

目标：

* 任务 CRUD；
* 今日任务；
* 月历视图；
* 完成、延期、跳过；
* 标签和优先级；
* 日程不会自动进入聊天 prompt。

### P4：角色联动

目标：

* 用户选择某篇日记后，角色可复盘；
* 用户选择今日日程后，角色可辅助安排；
* 用户确认后，日记或日程可提炼为长期记忆。

### P5：Windows 桌面端

目标：

* 使用桌面端 UI；
* 借鉴纸张感、便签感、卡片式排版；
* 统一聊天、日记、日程体验。

## 9. 验收标准

总体设计完成后，系统应满足：

* 主功能只有聊天、日记、日程；
* 角色和记忆作为底层能力嵌入三大功能；
* 日记和日程不自动进入聊天 prompt；
* 长期记忆必须由用户确认；
* 固定核心人设不可被 AI 自动修改；
* 可变补充人设可以压缩、归档；
* 本地单用户模式稳定运行。
