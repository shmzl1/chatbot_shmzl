# 聊天功能设计

## 1. 功能定位

聊天是虚拟人物陪伴系统的核心交互入口。

聊天负责：

* 虚拟人物陪伴；
* 普通问答；
* 情绪回应；
* 基于角色设定生成回复；
* 读取必要的关系记忆；
* 在用户主动选择时，围绕日记或日程进行交流。

聊天不是知识库管理器，也不是日记管理器，也不是日程管理器。
聊天只在需要时调用这些功能的数据。

## 2. 聊天输入来源

聊天默认读取：

```text
固定核心人设
pinned / always_read 关系记忆
当前会话上下文
少量相关 active 记忆
```

聊天不默认读取：

```text
全部日记
全部日程
全部聊天历史
archived 记忆
superseded 记忆
deleted 记忆
```

只有用户主动选择时，才额外读取：

```text
某篇日记
某个日程任务
某个计划
某次复习反馈
某段用户选中的历史对话
```

## 3. prompt 构造规则

每次构造聊天 prompt 时，应按照以下顺序组织上下文：

```text
1. 固定核心人设
2. 角色说话规则
3. pinned 关系记忆
4. 当前会话上下文
5. 少量相关 active 记忆
6. 用户主动选择的日记或日程内容
7. 当前用户输入
```

其中：

* 固定核心人设必须完整读取；
* pinned 记忆必须读取；
* 普通 active 记忆最多读取 8-12 条；
* 日记和日程必须由用户主动选择后才读取。

## 4. 角色人设读取

角色人设分为两类：

```text
固定核心人设
可变补充人设
```

固定核心人设包括：

* 角色身份；
* 角色名字；
* 核心背景；
* 核心性格；
* 核心关系定位；
* 核心说话原则；
* 核心禁止事项。

固定核心人设不可被 AI 自动修改，每次聊天必须完整读取。

可变补充人设包括：

* dialogues；
* reactions；
* bad_examples；
* evaluation_criteria；
* revision_notes；
* 用户反馈形成的补充样例。

可变补充人设可以被压缩、归档和去重。
聊天时不一定全部读取，可按 topK、摘要或固定上限读取。

## 5. 关系记忆读取

关系记忆用于保存用户确认后的长期偏好、习惯和关系理解。

记忆分为：

```text
pinned / always_read 记忆
普通 active 记忆
短期记忆
archived / superseded / deleted 记忆
```

读取规则：

* pinned 记忆每次必读；
* 普通 active 记忆按相关性和重要性读取 topK；
* 短期记忆未过期时可读取；
* archived、superseded、deleted 记忆不进入 prompt。

## 6. 与日记的关系

聊天默认不能读取全部日记。

允许读取日记的场景：

* 用户点击“让角色读这篇日记”；
* 用户点击“让角色复盘这篇日记”；
* 用户在聊天中明确指定某篇日记；
* 用户手动选择日记作为上下文。

不允许：

* 保存日记后自动进入聊天；
* 每次聊天读取所有日记；
* 未经用户确认自动从日记生成长期记忆。

## 7. 与日程的关系

聊天默认不能读取全部日程。

允许读取日程的场景：

* 用户点击“让角色看今日任务”；
* 用户让角色帮忙安排某个计划；
* 用户让角色复盘某个任务；
* 用户手动选择日程作为上下文。

不允许：

* 每次聊天读取所有日程；
* 自动把所有未完成任务变成长期记忆；
* 未经用户确认判断用户习惯。

## 8. 记忆写入规则

聊天中产生的长期记忆必须经过以下流程：

```text
聊天内容
↓
候选记忆
↓
查重和合并
↓
用户确认
↓
写入 relationship_memory
```

不能每次聊天都自动写入新记忆。

重复记忆应合并，不应无限新增。

例：

```text
旧记忆：用户不喜欢 AI 味太重的回复。
新候选：用户希望角色说话更像真实人物，不要工具式总结。
合并后：用户不喜欢 AI 味和工具式总结，希望角色回复更像真实人物。
```

## 9. 聊天页面设计

聊天页面建议布局：

```text
左侧：会话列表
中间：聊天窗口
右侧：角色状态 / 当前记忆提示 / 可选上下文
```

右侧不应堆太多管理功能。

记忆管理和角色管理可以放入设置或高级管理页面。

## 10. 验收标准

聊天功能应满足：

* 无需登录即可使用本地默认用户；
* 角色回复符合核心人设；
* 固定核心人设每次必读；
* pinned 记忆每次必读；
* 普通 active 记忆不会全部进入 prompt；
* 日记和日程不会默认进入 prompt；
* 用户主动选择日记或日程后，角色可以基于该内容回应；
* 聊天不会导致记忆无限增长。
