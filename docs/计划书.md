# 虚拟人物陪伴系统项目计划书

## 1. 项目定位

虚拟人物陪伴系统是一个本地运行的角色陪伴项目。它的核心目标是让用户和虚拟人物进行连续、可调整、有记忆感的对话。

项目当前边界是本地个人使用和开发调试，不以公开服务或商业化部署为目标。

## 2. 当前能力

- 本地默认用户，无注册、登录、密码或 JWT。
- 普通角色聊天接口。
- 日记 MVP：日记 CRUD、搜索筛选、图片附件、软删除。
- 聊天记录保存到本地 SQLite。
- 关系记忆事件保存到本地 SQLite。
- 角色包集中管理。
- 角色列表、详情、创建、更新、删除、恢复。
- 角色头像上传。
- 角色包校验。
- 人设反馈记录。
- 人设编辑 AI 多轮讨论。
- 最终人设修改 patch 和 `preview_character_json`。
- 用户确认后应用人设修改。
- 人设上一版备份和回滚。
- 可选 GPT-SoVITS 语音接口。
- 人物系统 debug 接口。
- relationship_memory 最小接口和 debug 查看。
- 人物包 CLI 工具。

## 4. 模块化原则

项目按业务模块拆分：

- `auth` 管理本地默认用户。
- `chat` 管理普通聊天。
- `diary` 管理日记、图片附件和用户主动选择后的日记上下文。
- `characters` 管理人物角色包。
- `persona_review` 管理人设编辑闭环。
- `memory` 管理长期记忆。
- `relationship_memory` 管理用户和角色之间的关系长期上下文。
- `knowledge` 管理知识库。
- `voice` 管理语音调用。
- `debug` 管理调试接口。

人设编辑、普通聊天、检索和语音配置都应通过 `modules.characters` 读取角色包。

## 5. 人物系统

人物系统集中在：

```text
backend/modules/characters/
```

每个角色一个独立目录：

```text
backend/modules/characters/packs/{character_id}/
  character.json
  voice_refs/
  backups/
```

`character.json` 是唯一必需文件。`voice_refs/` 保存本角色的本地语音参考素材。`backups/` 保存上一版人设文件，用于回滚。`.trash/` 用于安全删除后的角色包暂存。

## 6. 人设编辑闭环

人设编辑流程分为四步：

1. 用户选择聊天片段并写下评价。
2. 系统调用人设编辑 AI 讨论修改方向。
3. 系统生成最终修改 patch 和 `preview_character_json`。
4. 用户确认后才写入 `character.json`。

其中：

- `chat` 只讨论，不写文件。
- `finalize` 只生成预览，不写文件。
- `apply` 才写入角色包。
- `rollback` 只恢复上一版备份。

人设写入前必须校验角色包。写入失败不能覆盖原始 `character.json`。

人设字段必须分层：

- 固定核心人设：`id`、`display_name`、`core_personality`、`speaking_style`、`relationship_to_user`、`forbidden`、`reply_patterns`、`lore`、`style_contract`。AI 不能自动修改、删除、覆盖或压缩；聊天 prompt 每次完整读取。`avatar_url` 和 `voice` 是受保护元数据，也不能被人设编辑 AI 自动修改。
- 可变补充人设：`dialogues`、`reactions`、`bad_examples`、`evaluation_criteria`、`revision_notes`。AI 只能少量追加这些补充内容；用户确认 apply 后才允许压缩和归档。

可变补充上限为 `dialogues=20`、`reactions=20`、`bad_examples=20`、`evaluation_criteria=30`、`revision_notes=20`。被裁剪内容写入角色包 `backups/persona_compaction_archive.jsonl`，不能静默丢弃。

## 7. 关系记忆闭环

关系记忆集中在：

```text
backend/modules/relationship_memory/
```

数据库表为 `relationship_memory_events`。最小闭环包括：

1. 创建关系记忆。
2. 按 `character_id` 查看有效关系记忆。
3. 停用关系记忆。
4. debug 查看关系记忆事件。

普通聊天会读取当前角色有效关系记忆，并加入 prompt 的长期上下文。旧 `long_term_memories` 保留兼容，不在当前阶段删除。

如果聊天产生记忆建议，用户确认后应继续写入旧长期记忆，并额外写入 `relationship_memory_events`，记录来源会话和 turn。

记忆读取也必须分层：pinned / always_read 记忆每次 prompt 必读，不参与 topK；普通 active 记忆按相关性和重要度 topK 读取；短期记忆可设置 `expires_at`，过期后不进入 prompt。`archived`、`superseded`、`deleted` 和 `read_policy=never` 的记忆不得进入 prompt。

## 8. 日记 MVP

日记集中在：

```text
backend/modules/diary/
frontend/desktop/src/pages/DiaryPage.tsx
frontend/desktop/src/components/diary/
```

当前闭环包括：

1. 创建、查看、编辑和软删除日记。
2. 按关键词、日期、心情和标签筛选。
3. 上传 png、jpg、jpeg、webp 图片。
4. 软删除图片附件。
5. 用户主动点击“让角色读这篇日记”时，把该篇日记作为聊天上下文。

日记默认不进入聊天 prompt，不自动写入长期记忆。图片文件保存到 `uploads/diary/images/`，数据库只保存附件元数据，不保存 base64。

## 9. 数据保存和数据安全

SQLite 数据库保存聊天、日记、记忆、知识库、反馈和用户相关信息。默认文件是 `backend/data/chatbot.db`。人物包保存角色设定、示例对话、反应规则、语音配置和头像地址。

安全原则：

- 不提交 `.env`。
- 不提交真实私人聊天数据。
- 不提交官方素材、语音、模型权重。
- 删除角色时移动到 `.trash`。
- 不永久删除历史聊天。
- 人设修改前保留上一版备份。
- 停用关系记忆只更新 `is_active`，不物理删除事件。
- 日记和图片附件只做软删除。

## 10. 可选语音能力

GPT-SoVITS 是可选能力。如果配置了 GPT-SoVITS 服务，系统可以将角色回复转换为语音。

语音规则：

- `ref_audio_path` 必须存在。
- `prompt_text` 可以为空，这是 GPT-SoVITS 允许的。
- `neutral` 是默认语音参考。
- 用户没有明确选择 emotion 时使用 `neutral`。
- 用户明确选择 `angry`、`sad`、`happy` 等 emotion 时，必须存在对应参考音频。
- 明确 emotion 缺少参考音频时直接报错，不自动退回 `neutral`。
- 语音失败不影响数据库数据，但本次语音请求应明确返回错误。

## 11. 开发约束

- 不恢复模拟 provider 或隐藏错误的旧路径。
- 不静默吞掉角色包错误。
- 不绕过人物模块读写角色包。
- 不让 `chat` 或 `finalize` 直接写入人设文件。
- 不提交私人数据、素材和模型权重。
- 当前阶段不新增 QQ/微信接入或云部署能力。
- 不让聊天默认读取全部日记。
- 不从日记自动写入长期记忆。

## 12. 后续规划

后续可以逐步推进：

- 更完整的角色管理前端。
- 多人物创建、复制、导入和导出。
- 更完善的长期记忆摘要。
- 更细的关系记忆去重、合并和审计。
- 更细的人设变更审计。
- 语音素材管理界面。
- 日程 MVP。

这些能力应在现有模块边界内逐步实现。
