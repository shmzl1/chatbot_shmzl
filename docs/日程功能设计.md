# 日程功能设计

## 1. 功能定位

日程是三大主功能之一。

日程负责管理：

* 任务；
* 计划；
* 复习；
* 今日安排。

日程不是简单 todo，而是面向虚拟人物陪伴系统的行动管理模块。

未来角色可以在用户允许时辅助安排、提醒和复盘，但日程默认不进入聊天 prompt。

## 2. 参考方向

日程功能参考 Mnemo 的方向：

* 计划管理；
* 自动排程；
* 月历视图；
* 今日任务；
* 记忆状态反馈；
* 模糊 / 遗忘补救复习；
* 标签筛选；
* Markdown 笔记；
* 薄弱追踪。

第一阶段只做日程 MVP，不做完整复习系统。

## 3. 第一阶段功能范围

第一阶段实现：

* 新建任务；
* 编辑任务；
* 删除任务；
* 今日任务；
* 月历视图；
* 完成任务；
* 延期任务；
* 跳过任务；
* 标签；
* 优先级。

第一阶段暂不实现：

* 复杂智能排程；
* 云备份；
* 系统托盘提醒；
* Windows 通知；
* 完整 AI 规划；
* 多端同步。

## 4. 第二阶段功能范围

第二阶段实现计划和复习：

* 学习计划；
* 事项计划；
* 计划开始日期；
* 计划持续天数；
* 复习间隔；
* 自动生成复习任务；
* 记住 / 模糊 / 遗忘反馈；
* 补救复习；
* 薄弱任务追踪。

内置模板：

```
经典艾宾浩斯：1 / 2 / 4 / 7 / 15 / 30 天
密集冲刺：连续 6 天
每日任务：每天一次
自定义间隔：用户输入天数数组
```

## 5. 数据库设计

### 5.1 schedule_plans

```
id SERIAL PRIMARY KEY,
user_id INTEGER NOT NULL,
title TEXT NOT NULL,
description TEXT,
plan_type VARCHAR(32) NOT NULL,
start_date DATE,
end_date DATE,
review_template VARCHAR(64),
custom_intervals_json JSONB NOT NULL DEFAULT '[]',
tags_json JSONB NOT NULL DEFAULT '[]',
status VARCHAR(32) NOT NULL DEFAULT 'active',
created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
is_deleted BOOLEAN NOT NULL DEFAULT FALSE
```

plan_type：

```
normal
study
review
```

status：

```
active
paused
completed
archived
```

### 5.2 schedule_items

```
id SERIAL PRIMARY KEY,
plan_id INTEGER,
user_id INTEGER NOT NULL,
title TEXT NOT NULL,
note TEXT,
item_type VARCHAR(32) NOT NULL DEFAULT 'task',
priority INTEGER NOT NULL DEFAULT 3,
tags_json JSONB NOT NULL DEFAULT '[]',
created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
is_deleted BOOLEAN NOT NULL DEFAULT FALSE
```

item_type：

```
task
study_point
review_point
habit
```

priority：

```
1 = 最高
2 = 高
3 = 普通
4 = 低
5 = 最低
```

### 5.3 schedule_occurrences

```
id SERIAL PRIMARY KEY,
item_id INTEGER NOT NULL,

user_id INTEGER NOT NULL,
scheduled_date DATE NOT NULL,

occurrence_type VARCHAR(32) NOT NULL DEFAULT 'task',
status VARCHAR(32) NOT NULL DEFAULT 'pending',

created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
```

status：

```
pending
done
skipped
postponed

### 5.4 schedule_completion_logs

```
id SERIAL PRIMARY KEY,
occurrence_id INTEGER NOT NULL,
user_id INTEGER NOT NULL,

## 7. 前端页面设计

第一阶段在 `<span>frontend/simple_web</span>` 中新增日程页面。

布局：

```
左侧：计划列表 / 标签筛选
中间：今日任务 / 月历视图
右侧：任务详情 / 完成反馈
```

视觉风格：

* 轻量；
* 卡片式；
* 类似便签和计划纸；
* 不做复杂后台表格。

### 7.1 今日任务

显示：

* 任务标题；
* 计划来源；
* 优先级；
* 标签；
* 预计时间；
* 状态。

操作：

* 完成；
* 延期；
* 跳过。

### 7.2 月历视图

显示：

* 每天任务数量；
* 新增任务；
* 复习任务；
* 逾期任务。

第一阶段可以用简单月历网格，不引入复杂日历组件。

### 7.3 复习反馈

第二阶段实现：

* 记住；
* 模糊；
* 遗忘。

选择“模糊”或“遗忘”后，系统可自动生成补救复习 occurrence。

## 8. 与聊天和记忆的关系

日程不会自动进入聊天 prompt。

允许进入 prompt 的情况：

* 用户点击“让角色看今日任务”；
* 用户要求角色帮忙安排某个计划；
* 用户要求角色复盘今天完成情况。

不允许：

* 每次聊天读取所有日程；
* 自动把所有任务变成长期记忆；
* 未经用户确认自动生成关系记忆。

未来可提取的候选记忆：

* 用户不喜欢计划排太满；
* 用户更适合晚上学习；
* 用户长期任务容易拖延；
* 用户对某类复习内容更容易模糊或遗忘。

这些必须经过用户确认后才能写入 relationship_memory。

## 9. 验收标准

日程功能应满足：

* 可以新建任务；
* 可以编辑任务；
* 可以删除任务；
* 今日任务能显示；
* 月历能显示每天任务数量；
* 任务可以完成；
* 任务可以延期；
* 任务可以跳过；
* 日程不会自动进入聊天 prompt；
* 普通聊天不受影响。
