# 日记功能设计

## 1. 功能定位

日记是三大主功能之一。

日记负责记录：

* 生活事件；
* 情绪状态；
* 图片素材；
* 复盘素材；
* 用户阶段性想法。

日记是用户原始数据，不等于长期记忆。
日记默认不进入聊天 prompt。

## 2. 参考方向

日记功能借鉴 moodiary 的产品能力：

* 日记记录；
* 图片附件；
* 搜索分类；
* 心情与标签；
* 多媒体扩展方向。

UI 和排版借鉴 floral-notepaper 的方向：

* 轻量；
* 纸张感；
* 卡片式；
* 便签感；
* 适合 Windows 桌面端。

不直接复制开源项目代码，只借鉴功能和交互。

## 3. 第一阶段功能范围

第一阶段已实现日记 MVP：

* 新建日记；
* 编辑日记；
* 删除日记；
* 按日期查看；
* 搜索日记；
* 标题；
* Markdown 正文；
* 心情；
* 标签；
* 上传图片；
* 图片缩略图；

第一阶段暂不实现：

* 视频；
* 绘画；
* 地图轨迹；
* 天气自动获取；
* 密码锁；
* 云同步；
* 复杂富文本；
* AI 自动复盘；
* 自动写入长期记忆。

## 4. 数据库设计

### 4.1 diary_entries

当前字段：

```sql
id BIGSERIAL PRIMARY KEY,
user_id BIGINT NOT NULL REFERENCES users(id),
title TEXT NOT NULL DEFAULT '',
content_markdown TEXT NOT NULL DEFAULT '',
entry_date DATE NOT NULL,
mood TEXT NOT NULL DEFAULT '',
tags_json JSONB NOT NULL DEFAULT '[]',
is_deleted BOOLEAN NOT NULL DEFAULT FALSE,
created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
deleted_at TIMESTAMPTZ
```

字段说明：

* user_id：本地默认用户；
* title：标题，可空；
* content_markdown：Markdown 正文；
* mood：心情，例如 neutral、happy、calm、tired、anxious、sad；
* tags_json：字符串数组；
* entry_date：日记所属日期；
* is_deleted：软删除。

### 4.2 diary_attachments

当前字段：

```sql
id BIGSERIAL PRIMARY KEY,
entry_id BIGINT NOT NULL REFERENCES diary_entries(id),
user_id BIGINT NOT NULL REFERENCES users(id),
filename TEXT NOT NULL,
original_filename TEXT NOT NULL DEFAULT '',
content_type TEXT NOT NULL,
file_size BIGINT NOT NULL,
storage_path TEXT NOT NULL,
public_url TEXT NOT NULL,
is_deleted BOOLEAN NOT NULL DEFAULT FALSE,
created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
deleted_at TIMESTAMPTZ
```

第一阶段只支持 image。

图片保存在本地文件目录，数据库只保存路径和元信息，不保存 base64。

## 5. 图片保存规则

建议保存目录：

```text
backend/data/uploads/diary/images/
```

或复用项目现有 uploads 目录，在其下增加：

```text
uploads/diary/images/
```

支持格式：

```text
png
jpg
jpeg
webp
```

不支持：

```text
gif
svg
heic
bmp
```

命名建议：

```text
diary_{entry_id}_{uuid}.{ext}
```

删除图片时，第一阶段采用软删除数据库记录。
是否物理删除文件，可以后续通过清理工具统一处理。

## 6. 后端接口设计

日记 CRUD：

```text
GET    /diary/entries
POST   /diary/entries
GET    /diary/entries/{entry_id}
PUT    /diary/entries/{entry_id}
DELETE /diary/entries/{entry_id}
```

图片接口：

```text
POST   /diary/entries/{entry_id}/images
DELETE /diary/images/{image_id}
```

### 6.1 GET /diary/entries

查询参数：

```text
date_from
date_to
keyword
tag
mood
limit
offset
```

返回字段：

```text
id
title
excerpt
mood
tags
entry_date
image_count
created_at
updated_at
```

排序规则：

```text
entry_date DESC
updated_at DESC
```

### 6.2 POST /diary/entries

请求体示例：

```json
{
  "title": "今天的记录",
  "content_markdown": "今天写了项目文档。",
  "mood": "calm",
  "tags": ["项目", "学习"],
  "entry_date": "2026-06-11"
}
```

### 6.3 PUT /diary/entries/

允许修改：

* title；
* content_markdown；
* mood；
* tags；
* entry_date。

禁止修改：

* id；
* user_id；
* created_at。

### 6.4 DELETE /diary/entries/

采用软删除：

```text
is_deleted = true
```

### 6.5 POST /diary/entries//images

要求：

* 必须先存在 entry_id；
* 使用 multipart/form-data；
* 校验图片类型；
* 校验文件大小；
* 保存本地文件；
* 返回 image_id 和 public_url。

## 7. 前端页面设计

第一阶段在 `frontend/simple_web` 中新增日记页面，不重写整个前端。

布局：

```text
左侧：日记列表、搜索、日期筛选、标签筛选
中间：纸张式 Markdown 编辑区域
右侧：心情、标签、图片附件、保存按钮
```

视觉风格：

* 浅色背景；
* 柔和卡片；
* 纸张编辑区；
* 圆角；
* 轻微阴影；
* 不做后台管理系统风格。

### 7.1 日记列表

显示：

* 日期；
* 标题；
* 摘要；
* 心情；
* 标签；
* 图片数量；
* 更新时间。

标题为空时显示：

```text
日期 + 正文前 20 字
```

### 7.2 编辑区

字段：

* 标题输入框；
* Markdown 正文 textarea；
* 心情选择；
* 标签输入；
* 保存按钮；
* 删除按钮。

标签输入第一阶段可用逗号分隔。

### 7.3 图片区

功能：

* 上传图片；
* 显示缩略图；
* 删除图片。

上传前如果日记未保存，应提示：

```text
请先保存日记，再上传图片。
```

## 8. 与聊天和记忆的关系

日记不会自动进入聊天 prompt。

日记不会自动写入 relationship_memory。

当前已支持用户点击“让角色读这篇日记”，前端会向聊天请求传入该篇日记的 `diary_entry_id`。后端只读取这一篇日记，并把内容放入 prompt 的“用户主动提供的日记上下文”。

未来可扩展：

* 让角色帮我复盘；
* 从这篇日记提取候选记忆。

这些操作必须由用户主动触发。

候选记忆必须经过用户确认后才能保存。

## 9. 验收标准

日记功能应满足：

* 可以新建日记；
* 可以编辑日记；
* 可以删除日记；
* 可以按日期查看日记；
* 可以上传图片；
* 刷新后图片仍然显示；
* 删除图片后不再显示；
* 数据库不保存 base64 图片；
* 日记不会自动进入聊天 prompt；
* 普通聊天不受影响。
