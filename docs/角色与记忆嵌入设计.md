# 角色与记忆嵌入设计

## 1. 设计定位

角色和记忆不是独立主功能。

它们是聊天、日记、日程和设置共同调用的底层能力。

```
聊天 / 日记 / 日程 / 设置
        ↓
角色设定 + 关系记忆
```

## 2. 角色如何嵌入三个功能

### 2.1 嵌入聊天

聊天必须读取角色核心人设。

角色核心人设决定：

* 角色是谁；
* 角色如何说话；
* 角色如何回应用户情绪；
* 角色不能做什么；
* 角色和用户之间是什么关系。

### 2.2 嵌入日记

日记本身不是角色记忆。

用户可以选择让角色阅读某篇日记，然后角色基于人设进行陪伴式复盘。

角色不能未经允许主动读取全部日记。

日记中的内容如果要变成长期记忆，必须经过用户确认。

### 2.3 嵌入日程

日程本身不是角色记忆。

用户可以让角色查看今日任务、帮助安排计划、复盘完成情况。

角色给出的建议必须符合角色人设和用户已确认的记忆。

日程中的习惯判断如果要变成长期记忆，必须经过用户确认。

## 3. 角色分层

角色设定分为：

```
固定核心人设
可变补充人设
```

### 3.1 固定核心人设

固定核心人设包括：

* 角色身份；
* 角色名字；
* 核心背景；
* 核心性格；
* 核心关系；
* 核心边界；
* 核心说话原则；
* 核心禁止事项。

规则：

* AI 不能自动修改；
* 人设编辑 patch 不能写入；
* compact 逻辑不能裁剪；
* 每次 prompt 必须完整读取。

### 3.2 可变补充人设

可变补充人设包括：

* dialogues；
* reactions；
* bad_examples；
* evaluation_criteria；
* revision_notes；
* 用户反馈形成的补充样例。

规则：

* 可以由用户确认后追加；
* 可以压缩；
* 可以归档；
* 可以去重；
* 不应无限增长。

建议上限：

```
dialogues：20
reactions：20
bad_examples：20
evaluation_criteria：30
revision_notes：20
```

超过上限时：

* 保留早期核心样例；
* 保留最新高价值样例；
* 裁剪重复或低价值内容；
* 被裁剪内容写入归档；
* 归档内容不进入 prompt。

## 4. 记忆如何嵌入三个功能

关系记忆保存的是用户确认后的长期偏好、习惯和关系理解。

关系记忆不保存日记原文，也不保存全部日程原文。

### 4.1 嵌入聊天

聊天读取：

* pinned 记忆；
* 少量相关 active 记忆；
* 当前会话上下文。

### 4.2 嵌入日记

日记可以生成候选记忆，例如：

* 用户最近压力大；
* 用户喜欢晚上复盘；
* 用户不希望别人催促；
* 用户对某类话题比较敏感。

候选记忆必须经过用户确认后才能保存。

### 4.3 嵌入日程

日程可以生成候选记忆，例如：

* 用户不喜欢计划排太满；
* 用户更适合晚上学习；
* 用户长期任务容易拖延；
* 用户复习时容易忘记某类内容。

候选记忆也必须经过用户确认。

## 5. 记忆生命周期

记忆必须有生命周期。

建议字段：

```
status: active / archived / superseded / deleted
is_pinned: 是否固定记忆
is_editable: 是否允许 AI 自动建议修改
read_policy: always / relevant / never
importance: 1-5
confidence: 0-1
expires_at: 可空
last_used_at: 可空
use_count: 默认 0
supersedes_id: 可空
created_at
updated_at
```

### 5.1 pinned / always_read 记忆

特点：

* 每次 prompt 必须读取；
* 不参与 topK 裁剪；
* 不允许 AI 自动删除；
* 只能由用户未来手动管理。

适合保存：

* 用户明确要求永远记住的偏好；
* 用户明确设定的边界；
* 角色和用户之间的固定称呼或关系。

### 5.2 普通 active 记忆

特点：

* 按相关性 topK 读取；
* 可合并；
* 可替代；
* 可归档。

适合保存：

* 近期偏好；
* 任务习惯；
* 学习节奏；
* 常见情绪状态。

### 5.3 短期记忆

特点：

* 有 expires_at；
* 过期后不进入 prompt。

适合保存：

* 本周考试；
* 这几天压力大；
* 今天心情不好；
* 临时计划。

## 6. prompt 读取规则

每次 prompt 必须包含：

* 固定核心人设；
* pinned active 记忆；
* 当前会话必要上下文。

每次 prompt 可选择包含：

* 普通 active 记忆 topK；
* 可变人设样例 topK；
* 用户主动选择的日记；
* 用户主动选择的日程；
* 最近用户反馈。

禁止：

* 一次性读取所有普通记忆；
* 一次性读取所有日记；
* 一次性读取所有日程；
* 把 archived、superseded、deleted 记忆放进 prompt；
* 因为压缩导致核心人设丢失。

## 7. 不允许的设计

不允许把角色和记忆做成和聊天、日记、日程并列的主功能。

错误设计：

```
聊天
日记
日程
记忆
角色
```

正确设计：

```
聊天
日记
日程
设置
```

其中角色和记忆放在设置或高级管理中。

## 8. 用户控制原则

未来前端应提供高级管理能力。

用户应能：

* 查看角色记住了什么；
* 设置某条记忆为 pinned；
* 取消 pinned；
* 停用记忆；
* 删除记忆；
* 恢复记忆；
* 查看记忆来源；
* 查看被归档的人设样例。

## 9. 验收标准

实现后必须满足：

* 角色和记忆不作为独立主功能；
* 聊天、日记、日程都能调用角色和记忆；
* 核心人设不会被 AI 自动修改；
* 可变人设不会无限增长；
* pinned 记忆每次必读；
* 普通记忆不会无限塞进 prompt；
* 日记和日程不会自动泄露给聊天；
* 用户可以控制哪些内容被记住。
